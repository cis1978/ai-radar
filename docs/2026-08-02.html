01実務者の使い方は「会話」から「手順の再利用」へ移行した

Claude Code の実践論は 2026 年に入って構造が変わった。手作業でコンテキストを詰める段階は終わり、プランモード、並列探索、永続的なプロジェクトメモリ、長時間セッションの継続といった「型」が中心になっている。専門家が推す使い分けは明快で、絶対に守らせたいことは Hooks、業務知識は Skills、責務の切り分けは Subagents という三分割。ブレインストーミング、subagent 駆動、git worktrees、Research-Plan-Implement パターンなどが日常のワークフローとして定着している。

転用アイデア

自分の定型業務（週次レポート、議事録処理、請求書チェックなど）を1つ選び、手順を Markdown に書き出して「スキル」化する。次回から会話で説明し直す必要がなくなる。まずは説明が面倒な業務＝効果が大きい業務、と考えて選ぶとよい。

02Slackbot が「AIエージェント」化し、ユーザー定義の Skills を持つようになった

Slack はネイティブの MCP サーバーを持ち、Slackbot から Jira・Notion・Google・DocuSign のライブデータを会話の中に直接引き込めるようになった。さらに重要なのは、繰り返し作業に対して自分で「Skills」を定義できる点（例：定例のアジェンダ作成）。過去の会話や決定を覚えるメモリ機能、音声ディクテーション、ワークスペースのデータからのチャート生成も入った。書き込み系アクションは手動確認が必須で、管理者がMCPのアクセス範囲を制御する設計。合わせて Today View（当日の予定・タスク・優先事項を1画面に集約、Business+/Enterprise から順次）と Focus Mode（全プラン提供）も追加。

転用アイデア

ここでも中心は Skills、つまり手順を書いて再利用するという第1項と同じ構造。自分が毎週 Slack で繰り返している作業（定例のアジェンダ、進捗の取りまとめ）を1つ Skill として定義する。Focus Mode は全プランで使えるので、今日から試せる。

2026年6〜7月のアップデートで、AIミーティングノートが音声アップロードと話者ラベルに対応。加えてカスタムエージェントが iOS アプリでも使えるようになり、選択できるAIモデルも拡大した（GPT-5、Gemini、Claude など）。Slack や Google Drive との連携は標準機能。
